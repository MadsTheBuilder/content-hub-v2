# Task T2.2: Server-Side Content Library Search

## Summary
Migrated content library title filtering from client-side JavaScript to server-side PostgreSQL ILIKE query parameter.

## What Was Done

### Backend Changes
- **File**: `backend/content/router.py`
  - Added `Optional` import from `typing`
  - Updated `/library` endpoint signature to accept `search: Optional[str] = None` parameter
  - Added server-side filter: `if search: query = query.ilike("title", f"%{search}%")`

### Frontend API Changes
- **File**: `frontend/lib/api.ts`
  - Updated `library()` method params type to include `search?: string`
  - Added `if (params?.search) query.set("search", params.search);` to pass search param to API

### Frontend Page Changes
- **File**: `frontend/app/content/library/page.tsx`
  - Modified `loadContent()` to include search parameter: `if (debouncedSearch) params.search = debouncedSearch;`
  - Updated `useEffect` dependency array to trigger reload on `debouncedSearch` changes
  - Removed client-side filtering: deleted the `const filteredItems = ...` variable and its filter logic
  - Items now rendered directly from server-filtered response

## Files Changed
1. `backend/content/router.py` — Added search parameter and ILIKE filtering
2. `frontend/lib/api.ts` — Added search param to library() method

## Behavior
- User types in search box
- Frontend debounces input (200ms timer)
- On debounce change, triggers `loadContent()` which sends `?search=value` to backend
- Backend queries: `SELECT * FROM content_items WHERE title ILIKE '%value%'`
- Results returned to client, displayed immediately
- No client-side filtering; server handles all search logic
