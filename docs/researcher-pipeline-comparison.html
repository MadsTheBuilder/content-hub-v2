Three approaches: keyword filtering → semantic verification → full documentation context

The progression: Each approach addresses a limitation of the previous one.


Keyword filtering (BEFORE): Failed because repo names are ambiguous. mercury-agent returns sources about chemistry, not AI agents. The filter created a false binary: either you keep wrong sources or you strip relevant research material.


Semantic verification (AFTER): Solves the ambiguity problem. sources.get_guide() returns content summaries, and Claude Haiku makes a judgment call based on actual meaning, not URL tokens. This works reliably: mercury sources are dropped, Anthropic/Mythos articles are kept because they describe relevant concepts.


Full documentation context (ENHANCED): Adds a critical dimension: understanding how and when to use the repo. Instead of just README + web search, the researcher crawls the repo's own documentation — /docs, guides, API references, tutorials. These sources are added to the notebook alongside web research, providing LLM context on:

  • Core use cases and design philosophy
  • Key concepts and mental models
  • Common patterns and anti-patterns
  • When to use / when not to use

This context is extracted and embedded in the research prompt, so research questions are answered not just with factual accuracy, but with semantic depth. The brief becomes more useful because the LLM knows the repo's purpose and constraints before answering.
