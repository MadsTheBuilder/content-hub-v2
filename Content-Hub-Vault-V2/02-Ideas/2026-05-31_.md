# Video Ideas — 

### Rank 1 — Your AI-Coded App Looks Like Slop — This One Command Fixes It

**Angle:** Instead of "extract colors from a website," this is about feeding a *real, structured design system* into Claude Code / Cursor / Windsurf via MCP so the agent stops generating generic gray-and-blue UIs.

**Gap it fills:** Every existing design-extraction video stops at "here's a Chrome extension that grabs HEX codes for designers." Nobody connects extraction to the AI-coding-agent workflow — which is the exact thing the audience is doing right now and getting ugly results from.

**Audience desire:** They search "how to copy a website design," but what they actually want is "how do I make the code my agent writes look like a real product and not a Bootstrap demo."

**Competitive signal:** The hero tool ships an MCP server specifically for Claude Code/Cursor/Windsurf, and the trending board is dominated by vibe-coding harnesses (vibecode-pro-max-kit, the ADHD coding skill) — proven appetite for "make my agent output better" content.

**Hook direction:** Put two AI-generated landing pages side by side — one with a fed design system, one without — and say "Same prompt. Same model. One command is the difference."

**Format recommendation:** Long-form 8–15min — the side-by-side build and MCP wiring needs a real demo to land and to justify the payoff.

### Rank 2 — I Cloned Stripe's Entire Design System in 30 Seconds

**Angle:** Pure spectacle demo — point one CLI command at a famously well-designed site and reconstruct its tokens, Tailwind config, and component anatomy live.

**Gap it fills:** Existing "extract design" content shows you a color palette panel. Almost none show the *architecture* coming out — layout system, spacing scale, typed React stubs, responsive rules — which is the part that actually feels like magic.

**Audience desire:** "Can I just copy the design of a site I admire instead of starting from a blank Figma file?"

**Competitive signal:** The research explicitly contrasts this tool against others: *"Other tools give you the paint. designlang reads the architecture."* That quote is the whole video — it's a built-in differentiator nobody's filmed yet.

**Hook direction:** Open mid-action — terminal already running — "This is Stripe's site. In 30 seconds I'll have its design system as code. Watch the file count climb."

**Format recommendation:** Both — long-form for the full teardown, 60–90s short cut on the raw "command → files appear" moment as the discovery hook.

### Rank 3 — I Made an AI Grade My Website's Design. It Gave Me a D.

**Angle:** Run the "Design Report Card" (A–F grades) on your own site, react to the roast, then fix the failures on camera.

**Gap it fills:** Design feedback content is either vague ("trust your eye") or paid critique. A deterministic letter grade with specific failures is a format that doesn't exist for design and is wildly shareable.

**Audience desire:** "Is my design actually good, or am I just used to looking at it?" — they want an objective verdict, not opinions.

**Competitive signal:** The tool outputs a literal "Design Report Card (letter grades A–F)" plus CSS health audit scoring — a ready-made judgment mechanic, and roast/grade formats reliably overperform.

**Hook direction:** "I think my site looks pretty good. I'm about to let an AI grade it out loud. This is going to hurt." Cut straight to the grade reveal.

**Format recommendation:** Both — the grade reveal is a perfect short; the fix-it walkthrough seeds the long-form. High series potential: grade other people's submitted sites in episode 2.

### Rank 4 — Design Tokens Confused Me for a Year — This 3-Layer System Fixed It

**Angle:** Use the primitive → semantic → composite token structure (DTCG) as the spine of a genuinely clear explainer, taught against a real extracted example instead of theory slides.

**Gap it fills:** Most token explainers are abstract or vendor-marketing. Almost none teach the three-layer mental model concretely, and fewer still show the W3C DTCG JSON that's becoming the standard.

**Audience desire:** "Everyone says 'use design tokens' — what is a token actually, and why three layers instead of one variables file?"

**Competitive signal:** The research breaks tokens into exactly "primitive, semantic, and composite layers" of W3C-compliant DTCG JSON — a clean, citable structure that gives the video a real backbone.

**Hook direction:** "You've been told to use design tokens. Nobody told you there are three kinds — and mixing them up is why your theme breaks every time you rebrand."

**Format recommendation:** Long-form 8–15min — foundational/evergreen, and it's the seed for a whole tokens series (theming, dark mode, multi-brand).

### Rank 5 — Extract a Design Once, Ship It to iOS, Android, Web, and WordPress

**Angle:** One extraction → simultaneous emit to SwiftUI, Jetpack Compose, Flutter, Tailwind v4, shadcn/ui, and WordPress, showing the *same* design rendered across all of them.

**Gap it fills:** Cross-platform design consistency is usually a manual, painful sync problem. No one shows a single source-of-truth extraction fanning out to native platforms automatically.

**Audience desire:** "How do I keep my mobile app, web app, and marketing site from looking like three different products?"

**Competitive signal:** The README lists multi-platform emitters explicitly — iOS SwiftUI, Android Compose, Flutter, WordPress, Tailwind v4, Figma variables, shadcn/ui — an unusually broad output matrix that's never been shown side by side on video.

**Hook direction:** Four devices on a desk. "Same design. iPhone, Android, web, WordPress. I generated all four from one command — here's how."

**Format recommendation:** Long-form 8–15min — the multi-target payoff only impresses when you see each platform rendered.

### Rank 6 — Auto-Fix Every Accessibility Violation on Your Site (Without Touching Design)

**Angle:** Focus on WCAG contrast remediation that doesn't just flag failures but suggests the *nearest palette color* that passes AA/AAA — so you stay on-brand while becoming compliant.

**Gap it fills:** Accessibility content is mostly "here's why it matters" guilt-tripping or manual checklists. The "automatically suggest the closest passing color" mechanic is rarely shown and removes the usual designer objection that fixes ruin the brand.

**Audience desire:** "I know I should fix contrast, but I don't want my palette to turn ugly — give me compliant *and* on-brand."

**Competitive signal:** The tool "score[s] every foreground/background pair for contrast and suggest[s] the nearest palette color passing AA/AAA for every failing pair" — a specific, demoable capability with real legal/compliance search intent behind it.

**Hook direction:** "Your site is probably breaking accessibility law right now. The fix usually wrecks your colors — this one keeps them."

**Format recommendation:** Long-form 8–15min — pairs naturally with a compliance/audit angle that keeps pulling search traffic.

### Rank 7 — This Tool Reverse-Engineers a Brand's Writing Voice From Its Website

**Angle:** The unexpected feature — extraction that reads *brand voice*: tone, pronoun posture, and CTA verb inventory — not just visuals.

**Gap it fills:** Every design-extraction discussion is about pixels. The idea that you can extract *copy voice* programmatically is genuinely surprising and completely uncovered.

**Audience desire:** "How do I make my copy sound like a real brand instead of generic startup-speak?"

**Competitive signal:** The research lists a "Brand Voice" output that "analyzes tone, pronoun posture, and CTA verb inventory" — a left-field capability buried in a design tool, which makes it a strong curiosity hook.

**Hook direction:** "You can extract a website's colors. You can also extract how it *talks* — its exact pronouns, its CTA verbs, its tone. Watch."

**Format recommendation:** Short-form 60–90s — the surprise is the whole payload; it works best as a punchy "wait, you can do *that*?" clip that funnels to the main extraction video.

### Rank 8 — Steal a Website's Animations: Extracting Motion, Easing, and Springs

**Angle:** Capture the *motion language* — durations, easing curves, spring physics — as reusable motion tokens, then replay them in a fresh component.

**Gap it fills:** Motion is the hardest thing to copy by eye and almost nobody teaches extracting it. Most "recreate this animation" content is manual guesswork in DevTools.

**Audience desire:** "That site feels expensive because of how it moves — how do I get *that* feel without reverse-engineering it frame by frame?"

**Competitive signal:** The tool captures "Motion Tokens... durations, easings, and spring detection" — spring detection in particular is a specific, rarely-discussed capability worth a whole video.

**Hook direction:** "This animation feels expensive. I'm going to extract the exact easing and spring values behind it — no guessing in DevTools."

**Format recommendation:** Short-form 60–90s — motion is inherently visual and loops beautifully; ideal for a satisfying before/after match.

### Rank 9 — Catch Design Drift Before It Ships: Visual Diffs in Your CI Pipeline

**Angle:** Position extraction as a *CI guardrail* — drift checks and visual-diffs against a live source-of-truth so design regressions fail the build like a broken test.

**Gap it fills:** Design QA in CI/CD is barely covered for solo devs and small teams; existing content treats extraction as a one-time grab, not a continuous check.

**Audience desire:** "How do I stop my design system from silently rotting every time someone ships a 'quick fix'?"

**Competitive signal:** The research notes "drift checks against a live source-of-truth" and "visual-diffs to identify design regressions during CI/CD pipelines" — a concrete, advanced workflow that signals a more technical, retention-heavy audience.

**Hook direction:** "Your tests catch broken code. Nothing catches broken design — until someone screenshots it on Twitter. Let's fix that in CI."

**Format recommendation:** Long-form 8–15min — it's a setup/workflow piece; the value is in seeing the pipeline fail on a real regression.
