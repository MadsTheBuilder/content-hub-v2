# Session: T1.2 — Multi-User Auth Hardening (Supabase JWT)

## What Was Done

Completed multi-user authentication hardening by ensuring all protected endpoints require valid Supabase JWT tokens. The core JWT validation logic was already implemented; this session verified completeness and fixed one missing auth header injection.

### Verification Results

All 5 required files verified for complete implementation:

1. **backend/auth/dependencies.py** — JWT decode logic with mock-mode fallback ✓
   - Imports `jwt` from PyJWT library
   - Decodes Authorization header Bearer token
   - Extracts user_id from JWT payload's "sub" claim
   - Returns CurrentUser or raises HTTPException(401) on failure
   - Falls back to DummyUser if SUPABASE_JWT_SECRET not configured

2. **backend/auth/router.py** — Real Supabase auth endpoints ✓
   - `/signup` uses `supabase_client.auth.sign_up()`
   - `/login` uses `supabase_client.auth.sign_in_with_password()`
   - Both return JWT access_token from responses
   - Mock mode fallback for test environments

3. **frontend/lib/api.ts** — Authorization header injection ✓
   - `getToken()` retrieves JWT from Supabase session
   - All `fetchAPI()` calls inject `Authorization: Bearer ${token}` header
   - 401 responses trigger logout and redirect to `/login`
   - **FIXED:** uploadLogo now includes auth header (was missing before)

4. **frontend/app/layout.tsx** — Auth guard wrapper ✓
   - AuthProvider component wraps all children
   - Checks for active Supabase session on mount
   - Redirects unauthenticated users to `/login`

5. **frontend/app/login/page.tsx** — Login form ✓
   - Email + password form fields
   - Calls `supabaseClient.auth.signInWithPassword()`
   - Redirects to `/` on success
   - Link to signup for new users
