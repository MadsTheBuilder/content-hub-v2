# Is OpenMythos Legit? I Checked Every Claim Against Anthropic's Docs

OpenMythos showed up as an open-source PyTorch project. It aimed to rebuild Anthropic’s rumored Claude Mythos architecture. It suggested a new way to scale models: "recurrent depth" instead of just adding layers. But is it real, or just talk?

## What OpenMythos Claims

The core idea is simple: a model can "think deeper." It does this by looping through the same layers again and again. This is different from how old models work. They just stack hundreds of unique layers. OpenMythos uses a Recurrent Depth Transformer to make this happen. So instead of a big stack, one computational block loops up to **16 times**.

The architecture has three parts:
*   **The Prelude:** Regular transformer blocks take the first input.
*   **The Recurrent Block:** Layers with shared weights loop over and over. An "update rule" adds the first input encoding back in each time. This keeps the model from getting lost and forgetting what it started with.
*   **The KOD:** The last layers turn the refined hidden state into output tokens.

OpenMythos also does "Silent Reasoning." It thinks internally, in its latent space. It doesn't spit out visible "chain-of-thought" tokens. The beauty of this is simple: it cuts token costs and makes things faster. For efficiency, it uses Mixture of Experts (MoE) and Multi-Latent Attention (MLA). This means only about **5%** of its parameters wake up for each pass. And that saves a ton of memory.

## The Performance Claims and Controversy

The biggest claim is a **770 million** parameter OpenMythos model matches a **1.3 billion** parameter giant. That claim got called out right away. People said the project was "credential laundering." They claimed this performance number came from the "Parse" research paper. That paper came out **five days** *before* OpenMythos even existed.

Here are some other problems:
*   **No Weights or Benchmarks:** The repo has zero trained weights. No benchmarks. No one has reproduced the results. It’s just a "PyTorch scaffold." Or "fanfiction with a requirements.txt."
*   **Code Reliability:** A reviewer found **21%** of the author's own tests failed. This was on the main branch. That even included a key "stability guarantee." It was supposed to stop numerical explosions when the model looped.

## The Verdict: Research Playground, Not Production-Ready

Kai Gomez made this. He's known for quick open-source code. He's also been accused of "autogenerated" repos. And he's been in controversial crypto projects. Even OpenMythos's media coverage got questioned. People thought it might be sponsored content.

So, here's the deal. OpenMythos is a solid research piece. It's a good architectural experiment. This is true if you're looking into test-time compute and making parameters more efficient. But it is *not* a finished model stack. It doesn't have "production confidence." Think of it like a "research playground." It's for figuring out how a model like Claude Mythos *could* work. It's not a real replacement for big, frontier models.

## Key Takeaway

Don't expect OpenMythos to be a ready-to-go model. See it as experimental code. It shows you some cool things about recurrent depth architectures. And it proves they *can* be efficient.
